# Owned runtime and guest sources

The repository and static site distribute five owned QEMU executable bundles and one shared owned Alpine guest under `public/runtime/qemu/bundles/`. S1 V2/V3 and Server V1/V2/V3 retain separate compatibility identities. Their exact bytes and shared kernel/initramfs/firmware/root packages are pinned in the catalog and per-bundle provenance. The owned guest is Alpine 3.21.4 with Linux 6.12.38-0-virt. Legacy guests, including the older QEMU demo guest with Linux 6.12.43-0-virt, remain browser downloads from the origins in the existing provenance records.

The corresponding-source companion is [terrarium-s2-runtime-corresponding-source.tar.gz](https://github.com/niklas-olsson/niklas-olsson.github.io/releases/download/runtime-sources-s2/terrarium-s2-runtime-corresponding-source.tar.gz). The [public source manifest](../public/runtime/qemu/source-manifest.json) binds its exact complete size and SHA256, format and inventory identity. Retrieve that asset and verify its size, digest and closed membership as described below. The URL and digest specify the artifact; they do not certify live availability. Binary publication requires a separately verified anonymous retrieval of the exact companion. Hash-only upstream links do not replace delivery of this companion.

The companion contains 39 unchanged upstream inputs: the 37 target source/extraction inputs selected by the original distribution recipe, plus Netbase `protocols-6.4` and `services-6.4`, required by Alpine baselayout's APKBUILD and verified against its SHA512 declarations. Their original URLs, byte counts, SHA256 and applicable SHA512 appear in `build/qemu/distribution/manifest.json`. This is a newly assembled neutral archive with its own identity. It is not recovery of an older whole-file archive or evidence of a historical source delivery receipt.

## Components and terms

QEMU comes from the pinned `ktock/qemu-wasm` revision `0ef7b4e2814b231705d8371dd7997f5b72e70baf`. Its GPL terms and separately licensed portions are described in `public/runtime/qemu/QEMU-LICENSE.txt`, `QEMU-COPYING.txt` and the original component notices. Runtime dependencies include GLib, libffi, pixman, zlib, PCRE2, GVDB, device-tree/keycode data, SoftFloat/TestFloat and xterm-pty. Emscripten source is pinned to revision `047b82506d6b471873300a5e4d1e690420b582d0`; its MIT/University of Illinois/NCSA and bundled component notices remain intact.

The owned root's package/version/license/source-recipe declarations are retained in `build/qemu/distribution/guest/packages.json` and `installed-packages.txt`. They include BusyBox and Alpine baselayout under GPL-2.0-only, musl under MIT, and component-specific terms for package management, certificates, cryptography and utilities. Linux 6.12 plus patch 6.12.38, Alpine kernel patches/configuration, all selected aports recipe files (including three upstream post-upgrade symlink aliases materialized as regular copies of their original targets), and source archives for identified root/initramfs components accompany them. Kernel configuration and System.map bind the supplied kernel identity. The initramfs inventory is a list of file hashes, not exhaustive file-to-package provenance.

SeaBIOS and iPXE sources are pinned to the QEMU gitlink revisions. QEMU option ROM sources, firmware configurations and Makefiles are retained. `distribution/manifest.json` identifies the five supplied firmware binaries and their original archive members. Those binaries were selected from QEMU's archive rather than locally recompiled. SeaBIOS GPL/LGPL and iPXE GPL/UBDL notices, together with all other 159 retained component notice files, remain byte-identical under `public/runtime/qemu/licenses/`. Per-file upstream license and attribution headers remain in the original sources. Terrarium's Apache-2.0 license does not relicense any of these components.

The exact local modifications and their applicability are described in [the reconstruction instructions](../build/qemu/README.md): GLib runtime paths, the Emscripten proxy-context backport, QEMU address/context and segmented RAM corrections, and libffi unsigned addressing. Historical recipes remain unchanged in versioned reconstruction directories. The original generated pthread source and deterministic browser bootstrap transform accompany the recipes. Guest assembly, module overlay, filesystem configuration and packaging sources are included.

## Inspecting and rebuilding

The archive is a gzip-compressed POSIX tar with only regular files beneath `terrarium-s2-runtime-corresponding-source/`. Its closed [member inventory](../public/runtime/qemu/source-archive-members.json) identifies every payload member by path, byte count and SHA256. The archive includes that inventory at the same relative path. The inventory excludes itself to avoid a recursive hash; its bytes are bound by the external source manifest and the complete archive digest. No other unlisted member is permitted.

Verify the download against the complete size/hash in `source-manifest.json`, then use the checkout's `python3 -B build/qemu/source_archive.py verify --archive "$ARCHIVE"`. The verifier checks exact membership, regular-file types, safe paths, original input hashes and the embedded inventory without extracting anything. To extract a verified archive into a fresh directory:

```sh
mkdir source-kit
tar -xzf "$ARCHIVE" -C source-kit
cd source-kit/terrarium-s2-runtime-corresponding-source
```

`source-inputs/` contains original input files; all other paths mirror the public reconstruction closure. Follow `build/qemu/README.md` for host prerequisites, cache population, variant selection, compilation, guest assembly and package generation. The source companion contains reconstruction and adaptation sources, notices and records, not the complete application checkout or its shipped executable assets. Use a matching application checkout to run its preparation script after generating artifacts.

Rebuilding still fetches unchanged locked build inputs, including the prebuilt Emscripten SDK/compiler, Node helper, Alpine ISO/minirootfs, host tools and Python wheels. LLVM/Binaryen executable sources and a complete compiler bootstrap are not included in these 39 target inputs; no source-built compiler claim is made. Current recipes rebuild affected Emscripten system libraries from privately patched source. Kernel/initramfs/firmware are assembled from supplied binaries; their original compiler environments have not been reproduced. Source availability and passing closure checks do not establish byte-for-byte regeneration or application qualification. The initramfs provenance limitation needs independent component-obligation review; the delivery location alone cannot resolve it. Accessibility must be verified against the exact archive identity.
